# Android Emulator Setup — Windows

This guide covers setting up a local Android development environment on Windows for the **take** app. The app requires a development build (not Expo Go) because it uses a custom URL scheme (`take://`) for OAuth deep linking.

---

## Prerequisites

- [Android Studio](https://developer.android.com/studio) installed
- Android emulator created and running (Android Studio → Device Manager)
- Node.js 18+

---

## Step 1 — Set Environment Variables

These must be set in your PowerShell session **and** persisted permanently.

### ANDROID_HOME

```powershell
# Permanent (survives restarts)
[System.Environment]::SetEnvironmentVariable("ANDROID_HOME", "$env:LOCALAPPDATA\Android\Sdk", "User")

# Current session
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:PATH = "$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\emulator;$env:PATH"
```

### JAVA_HOME

Android Studio ships its own JDK. Use that instead of installing a separate JDK.

```powershell
# Permanent (survives restarts)
[System.Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Android\Android Studio\jbr", "User")

# Current session (required every new terminal until restart)
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
```

> **Note:** After setting permanent variables, restart your terminal (or log out/in) for them to take effect globally. Until then, set them per-session using the second block.

---

## Step 2 — Start the Emulator

You can launch the emulator from Android Studio (Device Manager → play button) or directly from the CLI.

### CLI launch (recommended)

```powershell
# List available emulators
emulator -list-avds

# Launch by name (use the name from the list above)
emulator -avd Android-Medium-Phone

# Launch in the background so the terminal stays free
Start-Process "$env:ANDROID_HOME\emulator\emulator.exe" -ArgumentList "-avd Medium_Phone_API_36"
```

If `emulator` isn't on your PATH, use the full path:

```powershell
& "$env:ANDROID_HOME\emulator\emulator.exe" -avd Medium_Phone_API_36
```

Keep the emulator running throughout your dev session.

**Recommended emulator settings:**
- RAM: **3072 MB minimum** (4096 MB recommended) — the app will OOM-crash and silently exit on lower values
- Change in: Android Studio → Device Manager → edit device → Show Advanced Settings → RAM

---

## Step 3 — Run a Development Build

The app uses a custom scheme (`take://`) for OAuth, which Expo Go does not support. You must use `npx expo run:android` to build and install a development client directly.

```powershell
cd student-app
adb devices
npx expo run:android
```

This will:
1. Run Expo Prebuild to generate the `android/` native project
2. Compile and install the app on your running emulator
3. Start the Metro bundler

> The `android/` directory is **gitignored** — it is fully generated by Expo Prebuild and should never be committed.

After the first build, you can start the bundler alone (faster) with:

```powershell
npm start
# Then press 'a' to open on the Android emulator
```

Only re-run `npx expo run:android` when native dependencies change (new packages that require linking, changes to `app.config.ts`, etc.).

## Troubleshooting

### `JAVA_HOME is not set` or `SDK location not found`

The permanent env var hasn't taken effect yet. Set it for the current session:

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
```

Then re-run `npx expo run:android`.

---

### `Unresolved reference 'R'` / `Unresolved reference 'BuildConfig'` (Kotlin compile error)

The generated `android/` directory is stale or has a package namespace mismatch. Delete it and let Expo Prebuild regenerate it:

```powershell
Remove-Item -Recurse -Force android
npx expo run:android
```

---

### `Unable to delete classes.jar` / Gradle file lock

A previous Gradle process is still holding a file lock. Stop all Gradle daemons and kill any lingering Java processes:

```powershell
.\android\gradlew.bat --stop
Stop-Process -Name "java" -Force -ErrorAction SilentlyContinue
```

Then re-run the build.

---

### App installs but immediately exits / black screen (OOM crash)

The emulator killed the app due to low memory. Check by running:

```powershell
adb logcat | Select-String "kill|oom|low memory"
```

If you see entries like `Kill 'com.take.dev'... reason: min watermark is breached`, increase the emulator RAM:

1. Open Android Studio → Device Manager
2. Edit your emulator → Show Advanced Settings
3. Set RAM to **3072 MB** or **4096 MB**
4. Cold boot the emulator

---

### `fetch failed` when running `expo start`

Expo CLI is trying to reach `api.expo.dev` and failing (corporate network, VPN, etc.). Start in offline mode:

```powershell
$env:EXPO_OFFLINE = "1"
npm start
```

Or pass the flag directly:

```powershell
npx expo start --offline
```

---

### `Unable to resolve "@react-native-async-storage/async-storage"`

A package (`amazon-cognito-identity-js`) requires this as a peer dependency. Install it with Expo's installer to get the SDK-compatible version:

```powershell
npx expo install @react-native-async-storage/async-storage
```

This is a JS-only package — no rebuild needed, just restart Metro.

---

### Metro cache issues after a rebuild

If the bundler shows stale module errors after a native rebuild:

```powershell
npx expo start --clear
```

## Google OAuth on the Emulator

Google sign-in via OAuth has quirks on the Android emulator:

- **"This account already exists on your device"** — this appears when the Google account is already registered as a system account on the emulator. Tap **Next** to proceed; if it won't advance, use a separate test Gmail account that isn't the emulator's system account.
- **Account picker vs email form** — on a real device, Google shows a native account picker sheet. The emulator shows the email text field instead. This is normal emulator behaviour.
- Email/password sign-in via the in-app form works identically on the emulator and does not have these limitations.

## Quick-Reference Checklist

Before each dev session, verify:

- [ ] Emulator is running (Device Manager → play button)
- [ ] `$env:JAVA_HOME` is set in the current terminal
- [ ] `$env:ANDROID_HOME` is set in the current terminal
- [ ] Metro bundler is running (`npm start`)
- [ ] App is installed (run `npx expo run:android` if not yet installed or after native dep changes)
