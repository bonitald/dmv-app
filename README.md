# DMV Prep

Colorado DMV written-permit-test practice app for teens. See `docs/prd.md` for full product
scope and `CLAUDE.md` for repo-level guidance.

## Stack

- Expo (managed, via `expo prebuild` / Continuous Native Generation) + React Native + TypeScript
- Custom dev client (`expo-dev-client`) — **not** Expo Go, per `docs/phase-0-findings.md`'s
  requirement for native modules (driving-timer Live Activity / foreground service).
- Firebase (Firestore, Auth, Analytics, Hosting) via `@react-native-firebase/*` (native SDK,
  not the JS SDK — see `ph-0-us-4`).

## Firebase setup (before first build)

The two Firebase projects' native config files (`google-services.json`,
`GoogleService-Info.plist`) are never committed (see ph-0-us-4's AC). Get them from whoever
holds `docs/phase-0-plan.md` Section C and place them at:

```
firebase-config/dev/google-services.json
firebase-config/dev/GoogleService-Info.plist
firebase-config/prod/google-services.json
firebase-config/prod/GoogleService-Info.plist
```

`app.config.ts` points `expo prebuild` at whichever of these matches `APP_ENV` (defaults to
`development` → `firebase-config/dev/`). Without them in place, `expo prebuild` /
`expo run:android` will fail looking for the config file. After adding them (or after
changing `APP_ENV`), re-run:

```
npx expo prebuild --clean
```

so the native project picks up the right file — the copy `expo prebuild` drops into
`android/app/google-services.json` (and the iOS equivalent) is itself gitignored, since it's
a straight copy of the same environment-specific keys.

## Native project directories (`ios/`, `android/`)

This project uses the CNG (Continuous Native Generation) workflow: `ios/` and `android/` are
generated by `expo prebuild` from `app.config.ts` (+ any config plugins added later) rather
than hand-edited. They're committed to the repo rather than gitignored — except the Firebase
config file `expo prebuild` copies into each (`google-services.json` /
`GoogleService-Info.plist`), which stays gitignored per environment (see "Firebase setup"
above). A fresh clone still needs those files placed and prebuild re-run once before its
first build; everything else about the native dirs is ready to go as committed.

**Convention**: never hand-edit files inside `ios/` or `android/` directly. All native
customization (e.g. Phase 6's Live Activity / foreground-service config plugins) must be
expressed as Expo config plugins in `app.config.ts`, then applied by re-running:

```
npx expo prebuild --clean
```

**Known gap**: `android/` is committed; `ios/` is not yet, because `expo prebuild` cannot
generate the iOS native project on Windows (Expo CLI requires macOS or Linux for the iOS
prebuild step). Generate it by running `npx expo prebuild --platform ios` from macOS/Linux
(or CI), or defer to EAS Build per `docs/phase-0-plan.md` Section D, which doesn't need a
local Mac at all.

## Setup

```
npm install
```

## Running

Custom dev client build (first run per platform, or after adding a new native
module/config plugin):

```
npm run android   # expo run:android — requires Android Studio SDK + a JDK on PATH
npm run ios       # expo run:ios — requires macOS + Xcode; not runnable from this Windows repo
```

Once a dev client build is installed on the device/emulator, subsequent iteration can use:

```
npm start
```

and reload against the installed dev client (not Expo Go — this project won't run in Expo Go
once native modules are added in later phases).

Web (for quick UI iteration only, not a target platform for the app):

```
npm run web
```
